# Vim 和 Neovim 心智模型

理解 Vim 和 Neovim，可以从文本如何进入内存、如何显示、如何编辑开始，再连接到工作目录、语言工具和运行时配置。具体命令的参数和版本差异可以用 `:help` 查询。

本文介绍通用概念，并单独标明本仓库的行为。内置 LSP、Lua 接口以及 lazy.nvim 等内容主要针对 Neovim；插件和用户映射也可能改变原生按键。

## 从 buffer 开始理解编辑器

buffer 是编辑器管理的文本与相关状态。编辑磁盘文件时，文件内容读入 buffer，修改首先发生在内存中，执行写入后才更新磁盘。保存也可能由插件或自动写入设置触发，不限于手动执行 `:w`。

buffer 还可以承载无名文本、终端输出、帮助文档或插件面板。它是理解文本编辑的入口，但工作目录、窗口布局、进程和插件状态都有各自的作用域与生命周期。

## 概念分类

| 类别 | 主要概念 | 回答的问题 |
| --- | --- | --- |
| 内容 | buffer | 内存中编辑和保存什么？ |
| 显示 | window、tab page | 在哪里显示，如何排布？ |
| 交互 | 模式、operator、motion、text object、Ex 命令 | 当前按键做什么，操作哪些文本？ |
| 属性 | filetype、buftype、modifiable、readonly | 内容是什么，buffer 如何使用，能否修改或写入？ |
| 历史与位置 | register、mark、jumplist、changelist、quickfix | 保存哪些内容和位置，如何返回？ |
| 语言能力 | LSP、Treesitter、diagnostics、completion | 代码分析来自哪里，结果如何显示？ |
| 运行时 | options、keymap、autocmd、runtimepath、插件加载 | 配置何时执行，对哪些对象生效？ |

## 内容与显示

### buffer 保存内容和编辑状态

buffer 包含文本、buffer 局部选项、修改状态、撤销历史等。一个 buffer 可以没有窗口显示，也可以同时显示在多个窗口中。

需要区分以下状态：

- **显示中**：buffer 正在某个窗口中显示。
- **隐藏但已加载**：没有窗口显示它，文本仍在内存中。
- **已卸载**：buffer 记录仍存在，但文本已不在内存中。
- **listed 或 unlisted**：是否出现在常规 buffer 列表中；这与是否加载、是否显示是不同维度。

`:ls` 或 `:buffers` 默认列出 listed buffer；`:ls!` 还包含 unlisted buffer。不能把所有未显示的条目都理解成“文本仍在内存里的隐藏 buffer”。

### window 显示 buffer

一个 window 在同一时刻显示一个 buffer；一个 buffer 可以被零个、一个或多个 window 显示。因此从“window 当前显示什么”来看，是**多个窗口可以指向同一个 buffer**，不是一对一或多对多。

```text
窗口 A ──→ buffer 1
窗口 B ──→ buffer 1
窗口 C ──→ buffer 2
           buffer 3（暂时没有窗口显示）
```

窗口可以在之后切换到另一个 buffer。两个窗口显示同一 buffer 时，共享文本和修改结果，但各自维护光标、视口及窗口局部选项。默认可以独立滚动，`scrollbind` 等设置也能让滚动联动。

`:split` 可以让两个窗口显示同一 buffer。关闭一个窗口通常不等于删除 buffer；能否离开未保存内容以及是否卸载，还受 `hidden`、`bufhidden` 和具体命令影响。参见 [窗口和 buffer 官方说明](https://neovim.io/doc/user/windows/)。

### tab page 组织窗口布局

tab page 是一组窗口的布局，不要求一个标签页只对应一个文件。同一个 buffer 也可以出现在不同标签页的窗口中；buffer 列表属于编辑器实例，不是每个标签页各自拥有一份。

常见窗口命令包括 `Ctrl-w h/j/k/l` 移动焦点、`Ctrl-w s/v` 分屏、`Ctrl-w q` 关闭窗口。`:bnext` 则是在当前窗口切换 buffer。两者操作的对象不同。

## 模式与编辑语法

### 模式决定按键如何解释

| 模式 | 主要用途 |
| --- | --- |
| Normal | 移动、删除、复制、执行编辑指令 |
| Insert | 连续输入文本 |
| Replace | 用输入内容替换已有字符 |
| Visual | 先选定范围，再执行操作 |
| Command-line | 输入 `:` 命令、`/` 搜索等 |
| Operator-pending | 已输入操作符，等待 motion 或 text object 指定范围 |
| Terminal | 将输入交给终端进程；退出到 Terminal-Normal 后可导航终端文本 |

Insert 不是唯一能修改或输入文本的模式。Replace、Normal 命令和 Ex 命令也能改变内容。熟悉模式的目的是让输入、导航和修改各自使用合适的操作。

### 操作符与范围组合

一个常见形式是：

```text
次数 + 操作符 + 移动或文本对象
```

- **operator**：`d` 删除、`c` 修改、`y` 复制、`>` 缩进、`gu` 转小写。
- **motion**：`w`、`}`、`G`、`f,` 等，确定移动目标或操作范围。
- **text object**：`iw` 单词内部、`i(` 括号内部、`it` 标签内部、`ip` 段落内部等。

例如 `diw` 删除当前单词内部，`ci(` 修改括号内文本，`yap` 复制包含相邻空白边界的段落。`i` 和 `a` 如何确定内部与外围范围，由具体文本对象定义。

文本对象通常用于操作符之后或 Visual 模式，不能把普通模式下单独按 `iw` 当作一个通用移动命令。也不是每个 Normal 命令都采用上述组合，例如 `x` 可以直接删除光标处字符。

### Ex 命令与范围

Ex 命令可以用于单步操作、交互确认和批处理，不限于非交互操作。常见结构可以写成：

```text
:[范围]命令[参数]
```

并非所有命令都接受范围，标志位的位置也由具体命令决定。例如替换命令才使用 `:s/模式/替换/标志` 的形式。

| 命令 | 含义 |
| --- | --- |
| `:%s/old/new/g` | 在全文每行替换所有匹配 |
| `:%s/old/new/gc` | 逐个确认替换 |
| `:1,10delete` | 删除第 1 到第 10 行 |
| `:'<,'>delete` | 删除上次 Visual 选区涉及的行 |
| `:g/TODO/d` | 删除匹配 TODO 的行 |
| `:g/^$/d` | 删除空行 |
| `:%normal! A;` | 对每行执行原生 Normal 命令，在行尾添加分号 |

普通 Ex 行范围按行处理，字符或块选区不会自动让每个 Ex 命令变成按字符或块处理。`normal!` 的 `!` 表示忽略用户映射，并非所有带 `!` 的命令都表达同一含义。

## buffer 属性

这些属性描述不同方面，不能用“真文件或面板”“只读或可写”两个简单分类代替。

| 属性 | 描述 | 例子 |
| --- | --- | --- |
| `filetype` | 内容类型，常用于选择语言或插件行为 | `python`、`lua`、`markdown`、`minifiles` |
| `buftype` | buffer 的特殊用途及读写规则 | 空字符串、`nofile`、`acwrite`、`quickfix`、`terminal`、`help`、`prompt` |
| `modifiable` | 是否允许修改 buffer 文本 | `false` 时阻止通常的文本修改 |
| `readonly` | 写入时是否按只读状态保护 | `true` 通常仍允许编辑，但普通写入会受阻 |
| `buflisted` | 是否进入常规 buffer 列表 | 插件面板经常设为 `false` |

`buftype` 为空表示普通 buffer，也可能是尚未命名、尚未保存的新文本。`nofile` 常用于非普通文件内容；`acwrite` 则让写入由自动命令接管。浮窗是窗口的显示形式，不对应某种固定的 `buftype`。

`readonly` 不是禁止修改，也不等同于操作系统文件权限。在文件系统允许等条件下，`:write!` 可以覆盖编辑器的只读保护；`:write!` 不会赋予操作系统本来没有的权限。`modifiable=false` 才会限制通常的 buffer 文本修改。参见 [选项官方说明](https://neovim.io/doc/user/options/)。

设置或检测出 `filetype` 后，通常会触发 `FileType` 事件，文件类型插件和相关工具据此工作。但具体功能还取决于是否启用、依赖是否就绪以及插件自己的条件。

本仓库关闭了 netrw 的插件入口，目录浏览由 mini.files 接管；其他配置可能使用 netrw 或不同的文件管理器。插件也可以根据 buffer 号、路径、窗口、`buftype` 等限制行为，不只根据 `filetype`。

## 内容记忆与位置历史

### register 保存文本或按键序列

寄存器可以存放复制、删除的文本，也用于录制宏。常见例子：

- `"ayy`：将当前行复制到 a 寄存器；`"ap` 从 a 寄存器粘贴。
- `"0p`：从 0 寄存器粘贴。普通 yank 通常更新它，普通删除不会；显式指定其他寄存器等情况会改变更新规则。
- `"+p`：从 `+` 系统剪贴板寄存器粘贴，需要可用的剪贴板支持。
- `"_dd`：删除到黑洞寄存器，避免更新通常由删除影响的寄存器。

默认复制和粘贴的行为还受 `clipboard` 选项影响。本仓库使用 `unnamedplus`，让普通复制、删除和粘贴通常与 `+` 寄存器协作；具体可用性取决于本机剪贴板提供者。

### mark 保存主动标记的位置

`ma` 设置当前 buffer 的小写标记 a，反引号加 a 跳回精确位置；单引号加 a 则跳到相应行的首个非空白字符。大写 A 到 Z 是文件标记，可用于跨文件跳转。

### jumplist 与 changelist 保存不同历史

jumplist 记录跳转位置，并非每次 `h/j/k/l` 移动都进入跳转历史。`Ctrl-o` 和 `Ctrl-i` 分别返回更早或更晚的位置；跳转列表与窗口相关。

changelist 记录修改位置，与 buffer 相关。`g;` 和 `g,` 在较早或较晚的修改位置之间移动。两者都不同于 undo：返回修改位置不会撤销修改。

### quickfix 与 location list 保存待处理位置

quickfix 是一组位置和消息，可以来自编译、grep、诊断或其他工具。它不是自动记录“去过哪里”的历史。

```vim
:copen
:cnext
:cprevious
```

location list 与窗口关联，可使用 `:lopen`、`:lnext`、`:lprevious`。某些 Neovim 版本提供 `]q`、`[q` 等默认映射，但 Vim、不同版本和用户配置可能不同，命令形式更便于核对基础行为。

## 语言能力与结果呈现

| 组件 | 负责什么 |
| --- | --- |
| LSP | 协议；Neovim 内置客户端通过它与语言服务器通信 |
| 语言服务器 | 根据支持的语言和能力提供分析、跳转、引用、补全、重命名等 |
| Treesitter | 在编辑器内解析文本，提供语法树，供高亮、折叠等功能使用 |
| diagnostics | 保存和展示诊断；LSP、linter 或插件都可以作为来源 |
| completion | 收集候选并处理显示、选择与插入；来源可以是 LSP、路径、buffer 文本和片段 |

### LSP 的配置、进程和挂载

LSP 是协议，不是进程名称。语言服务器通常是独立进程，Neovim 的 LSP 客户端管理连接。`attach` 表示客户端与某个 buffer 建立关联；同一客户端可以关联多个 buffer，一个 buffer 也可以关联多个客户端。

是否启动或复用客户端，取决于服务器是否启用、文件类型、项目根、启动命令和其他配置，不能只看 `filetype`。不同项目可能需要不同客户端，同一项目的多个文件则可能复用已有客户端。

本仓库的 Python 同时使用 Pyright 和 Ruff；项目根与解释器由 [core.python](../lua/core/python.lua) 从文件路径解析。安装服务器、启用配置、进程启动和成功 attach 是不同阶段。参见 [LSP 官方说明](https://neovim.io/doc/user/lsp/)。

### Treesitter 与 LSP 分工

Treesitter 提供语法结构，LSP 连接语言服务器提供语言分析。二者可以独立工作，也会被插件组合使用；LSP 也能提供语义高亮或折叠等能力，所以不能把所有高亮、折叠问题都归因于 Treesitter。

解析器、query 和使用语法树的功能也不是同一层：安装解析器不等于所有高亮、折叠或文本对象都已启用。语法文本对象通常需要相应插件与 query，本仓库的一部分文本对象则来自 mini.ai。参见 [Treesitter 官方说明](https://neovim.io/doc/user/treesitter/)。

排查时先确定结果由谁提供：跳转失败检查客户端和服务器能力；颜色异常检查主题、语法高亮、Treesitter 和语义高亮；补全异常还需检查候选来源及补全界面。

## 工作目录与项目根

Neovim 没有要求所有插件共享一个“当前项目”。以下目录可以不同：

| 状态 | 谁维护 | 主要影响 |
| --- | --- | --- |
| 全局工作目录 | Neovim | 相对路径和使用全局目录的操作 |
| 标签页或窗口局部目录 | Neovim | 覆盖相应上下文的实际工作目录 |
| 资源面板目录 | 文件浏览插件 | 当前浏览的目录和面板分支 |
| LSP 项目根 | 客户端配置与服务器 | 分析工作区、客户端复用等 |
| 终端进程目录 | shell 或其他子进程 | 进程内部执行命令的位置 |

`:cd` 修改全局目录，`:tcd` 设置标签页局部目录，`:lcd` 设置窗口局部目录。局部目录可以让其他窗口或标签页仍使用不同的实际目录。查看状态：

```vim
:pwd
:lua print(vim.fn.getcwd(-1, -1))
```

前者显示当前窗口实际生效的目录，后者查询全局目录。`cd 项目目录` 后启动 Neovim，与从其他目录执行 `nvim 项目目录` 不应混为一谈；打开目录参数本身不保证工作目录相同。

在本仓库，mini.files 中的 `l` 只负责浏览。`g=` 才会把聚焦面板目录设为 Neovim 全局目录，并以它为根重新打开面板，`=` 仍用于同步文件操作。

切换工作目录不会自动让已运行的 shell 执行 `cd`，也不会把已有 LSP 客户端或调试进程迁移到另一个项目。新搜索或新建终端是否采用新目录，还取决于调用参数和插件规则。参见 [编辑与工作目录官方说明](https://neovim.io/doc/user/editing/)。

## 运行时如何连接配置与功能

### runtimepath 与目录约定

runtimepath 是运行时资源的搜索路径，不代表其中所有子目录会被立刻执行。

| 目录 | 常见加载方式 |
| --- | --- |
| `plugin/` | 常规启动加载流程中执行；插件管理器也可延后执行 |
| `lua/` | 通常通过 `require()` 等方式加载，带模块缓存 |
| `ftplugin/` | 启用文件类型插件后，由 `FileType` 等机制加载对应配置 |
| `after/` | 对支持该约定的运行时加载流程提供较后的搜索或执行位置 |
| `queries/` | 对应的 Treesitter 功能需要 query 时读取 |

`after/` 不保证覆盖随后由懒加载插件、事件回调或显式赋值产生的所有设置。`ftplugin/python.lua` 的执行也依赖文件类型插件加载机制，不只是“文件扩展名是 .py”。参见 [启动与运行时官方说明](https://neovim.io/doc/user/starting/)。

### 选项与映射的作用域

选项可能是全局、buffer 局部或窗口局部，也可能有全局默认值和局部值共同作用。`filetype` 是 buffer 局部选项，`number` 是窗口局部选项。`:set`、`:setlocal`、`:setglobal` 的具体效果由选项类型决定。

映射则要同时看模式和作用域。同一模式中，buffer 局部映射通常优先于全局映射，所以 `g=` 可以只在 mini.files 中生效。

### 事件与回调

读取文件、进入窗口、确定文件类型、保存文件等操作会触发事件。autocmd 将事件与回调连接起来；登记回调不等于立即执行回调里的功能。

事件可能多次发生，回调也可能再次触发其他事件。配置需要考虑作用域、重复注册和异步结果到达时对象是否还存在。

### 插件与外部工具的生命周期

lazy.nvim 先读取插件声明，再根据启动规则、事件、文件类型、命令、按键或模块请求加载插件。加载可能涉及依赖、运行时脚本和 `setup()`，不仅仅是一句 `require()`。

| 对象 | 生命周期由谁维护 |
| --- | --- |
| 插件声明和加载状态 | lazy.nvim |
| 已加载 Lua 模块 | Lua 模块缓存，通常保持到 Neovim 退出 |
| buffer 和窗口 | Neovim 核心及调用相关 API 的插件 |
| LSP 客户端连接 | Neovim 内置 LSP 客户端 |
| 终端进程 | 终端相关代码与操作系统 |
| 调试会话 | DAP 插件与调试适配器 |
| 外部工具安装 | Mason 等工具管理组件 |

关闭插件面板不等于卸载插件，隐藏终端不一定结束进程，修改配置文件也不等于所有旧状态已清理。详细启动顺序见 [init.lua 启动配置详解](init-lua-guide.md)。

## 原生按键与本仓库映射

学习通用 Vim 操作时，需要区分原生行为与当前配置。常见差异：

| 按键 | 原生 Normal 行为 | 本仓库当前行为 |
| --- | --- | --- |
| `s` | 删除字符并进入 Insert | Hop 单字符跳转 |
| `S` | 替换当前行内容 | Hop 双字符跳转 |
| `gf` | 打开光标处文件路径 | 通过 Conform 格式化 |
| `gt` | 切换到下一个标签页 | 通过 Telescope 跳转类型定义 |

`f/F` 等也经过定制，且不同模式的映射可能不同。遇到教程与实际操作不一致，可以查看：

```vim
:verbose nmap gf
:verbose nmap s
:verbose omap f
:verbose imap <Tab>
```

`:help` 描述原生功能，`:verbose ...map` 帮助定位当前映射及来源。需要在干净环境练习原生行为时，可以使用 `nvim --clean`。

## 重复机制

`.` 重复上一次可重复的修改，不是重放任意操作或上次按键。许多原生编辑命令支持它，插件操作是否支持则取决于实现。

搜索替换可以使用 `cgn`：用 `/foo` 找到希望修改的匹配，在该匹配上执行 `cgn`、输入新文本、按 Esc。之后 `.` 可以修改下一个匹配，`n` 可以前往后续匹配。原生 `*` 会搜索并移动到下一个同词匹配，若要从原位置开始，需注意搜索后的光标位置。

宏用于记录和重放更长的按键过程：`qa` 开始录制到 a，`q` 结束，`@a` 重放，`@@` 重放最近执行的宏。宏会受当前 buffer、光标、搜索状态和映射影响，异步插件流程也不一定适合录制。`.` 和宏的规则参见 [重复命令官方说明](https://neovim.io/doc/user/repeat/)。

## 用帮助与观察建立自己的判断

常用帮助入口：

```vim
:help windows-intro
:help current-directory
:help 'buftype'
:help 'modifiable'
:help 'readonly'
:help operator
:help text-objects
:help :global
:help lsp
:help lua-guide
```

帮助窗口中 `Ctrl-]` 跳转帮助标签，`Ctrl-t` 沿标签栈返回；`Ctrl-o` 返回跳转列表中的较早位置，两种返回机制不同。

定位问题时依次问：正在操作哪个 buffer 或窗口？什么模式？实际目录是什么？设置或映射在哪个作用域？提供功能的插件或外部进程是否已就绪？这种检查顺序可以把“操作没反应”拆成具体、可观察的状态。
